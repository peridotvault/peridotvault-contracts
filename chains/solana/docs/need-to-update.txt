1) Executive Summary
================================================================
Status saat ini:
- PGL1: core flow game + license sudah berjalan dan access control dasar cukup jelas.
- Registry: onboarding + fee + grant + status management berjalan, tetapi ada trust boundary yang belum dikunci penuh pada CPI target.
- Game Store: masih partial/integration-stage. Ada gap fungsional besar pada settlement + license mint, dan ada indikasi incompatibility pada pembacaan account mirror eksternal.

Prioritas utama update:
- [CRITICAL] Dokumentasi harus menyatakan bahwa game-store belum full production untuk commerce settlement.
- [CRITICAL] Dokumentasi harus menyatakan buy_game saat ini hanya validasi + receipt (tanpa transfer SPL dan tanpa mint license).
- [HIGH] Dokumentasi harus menambahkan access/security matrix per instruction.
- [HIGH] Dokumentasi harus menambahkan trust assumptions dan limitasi CPI registry->pgl1.

================================================================
2) Critical Findings (Code + Doc Gaps)
================================================================
[CRITICAL-1] Game Store mirror model belum reliable untuk external program account.
- Gejala: flow store config/listing pernah gagal dengan AccountOwnedByWrongProgram (terlihat juga di test "currently rejects external ...").
- Dampak: listing/payment option untuk game registry canonical bisa gagal runtime.
- Action code:
  1. Ganti Account<SourceGameMirror>/Account<RegistryGameMirror> jadi model yang benar-benar kompatibel cross-program.
  2. Opsi A: gunakan type account canonical dari dependency program (pgl1::state::Game, registry::state::RegistryGame) via CPI crate.
  3. Opsi B: gunakan UncheckedAccount + manual deserialize yang explicit + owner checks + discriminator checks.
- Action docs:
  - Tambahkan warning besar bahwa mirror compatibility adalah known issue sampai patch final.

[CRITICAL-2] buy_game belum lakukan token settlement + license mint.
- Saat ini buy_game:
  - validasi price/status/token
  - hitung final_price/referral_bps
  - simpan PurchaseReceipt
- Tidak ada:
  - transfer token buyer->treasury/publisher/referrer
  - CPI mint license ke PGL1
  - check already-owned license
- Dampak: purchase belum merepresentasikan transaksi ekonomi final.
- Action docs:
  - Wajib tulis "buy_game = accounting receipt only (sementara)".
  - Jelaskan bahwa PaymentFailed/LicenseMintFailed/AlreadyOwned belum fully used.

[HIGH-1] Registry create_game_and_register: trust boundary CPI belum ketat.
- pgl1_program adalah UncheckedAccount, tidak dipaksa ke allowlist/ID tertentu.
- pgl_config/pgl_treasury/pgl_creator_state/game juga forwarded tanpa verifikasi ekstra yang ketat terhadap canonical PGL1 config.
- Dampak: potensi misrouting CPI jika caller menyuplai account/target tidak sesuai asumsi integrasi.
- Action code:
  1. Tambah expected pgl1 program address pada RegistryConfig (atau allowlist PDA).
  2. Validate pgl1_program key == expected.
  3. Validate pgl_config PDA dan pgl_treasury terkait pgl_config.
- Action docs:
  - Tambah bagian "Current trust assumptions for CPI".

[HIGH-2] Inisialisasi config sering jadi akar masalah operasional.
- Jika pgl_config/registry_config/store_config belum ada, banyak menu/flow akan gagal.
- Action docs:
  - Wajib ada section "Bootstrap order" dan dependency graph sebelum operasi token/game.

[MEDIUM-1] Validasi non-default pubkey tidak konsisten.
- Store initialize_store/set_treasury tidak menolak treasury default.
- Store initialize_store juga tidak menolak store_actor default.
- PGL1/Registry sudah menolak treasury default.
- Action code/docs:
  - Samakan policy validasi agar konsisten lintas program.

[MEDIUM-2] Error semantics beberapa tempat tidak presisi.
- Contoh: overflow next_nonce di create_game map ke GameAlreadyExists.
- Action docs:
  - Tambah note bahwa beberapa error code belum granular.

4) Flow Per Instruction (What Docs Must Explain)
================================================================
Docs harus menambahkan "Flow" minimal seperti ini:

PGL1.create_game
1. validate input
2. optional SOL fee transfer ke treasury
3. init_if_needed creator_state
4. derive game PDA by nonce
5. write game + increment nonce

Registry.create_game_and_register
1. validate game_id + metadata_uri
2. check publish grant opsional
3. jika tidak grant aktif -> transfer_checked registry fee
4. CPI call create_game di pgl1
5. init registry_game status Active

Store.init_game_store_config
1. verify authorized source+registry program
2. verify ownership and game linkage
3. verify registry status Active
4. write initial game store config

Store.set_game_payment_option
1. verify publisher ownership + registry active
2. verify game_store_config active
3. verify accepted payment token active
4. write game payment option

Store.buy_game (current)
1. verify all status/token/price constraints
2. compute discount + referral bps
3. write purchase receipt
4. emit purchase event
5. STOP (no settlement/no license mint yet)
